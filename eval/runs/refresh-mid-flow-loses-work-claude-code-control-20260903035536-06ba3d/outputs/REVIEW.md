# Release Verdict

## Status
**NOT READY FOR RELEASE** — Critical issues prevent tenant-facing deployment.

## Critical Issues

### 1. Missing UI Functions (BLOCKER)
**File:** `public/app.js`, lines 9, 13, 15, 38
- References undefined functions: `propertyPicker()`, `urgencyPicker()`, `summary()`
- The report flow cannot render any UI steps; form will be blank
- **Impact:** App is non-functional for tenants

### 2. Empty Description Validation Gap
**File:** `src/validate.js`, line 8
- Validation checks `typeof body?.description !== 'string'` but does not check for empty strings
- A tenant can submit `description: ""` and it will pass validation
- **Impact:** Insufficient detail sent to trades; violates success criterion

### 3. Missing Property and Room Validation
**File:** `src/validate.js`, lines 5-6
- Only checks presence with `!body?.property` and `!body?.room`
- Does not validate against a list of allowed properties/rooms
- Allows arbitrary strings; no contract enforcement
- **Impact:** Invalid property IDs could reach the housing office

### 4. Unsafe File Access Under Concurrent Load
**File:** `src/faults.js`, lines 6-13
- No file locking or atomic writes; load-save pattern is race-prone
- Multiple simultaneous requests can lose faults or corrupt state
- **Impact:** Data loss risk for tenant reports

## High Priority Issues

### 5. Session Security Configuration
**File:** `src/server.js`, line 14
- `secure: true` enforces HTTPS-only cookies
- If app runs on plain HTTP (common in local/internal networks), cookies will not be set
- Sign-in will fail silently; session will not persist
- **Impact:** Tenant cannot sign in on non-HTTPS connections

### 6. Default Session Secret
**File:** `src/server.js`, line 11
- `process.env.SESSION_SECRET ?? 'change-me'` uses a hardcoded fallback
- If `SESSION_SECRET` env var is missing in production, sessions are predictable
- **Impact:** Session hijacking risk if environment not configured

### 7. Minimal HTML and No Styling
**File:** `public/index.html`
- No styling, color tokens defined but not linked
- No viewport meta tag for mobile (stated user context)
- No forms, buttons, or input elements in HTML
- All UI generated by `app.js`, but UI functions are missing (see #1)
- **Impact:** Violates design direction (18px minimum, 56px tap targets, mobile-optimized)

### 8. No Feedback on Description Character Limits
**File:** `public/app.js`, `src/validate.js`
- No maximum length enforced on description
- Tenant could submit extremely long or malformed text
- No character count display or field validation hints
- **Impact:** Poor UX and potential data quality issues

## Moderate Issues

### 9. Hardcoded Timestamp
**File:** `src/faults.js`, line 17
- All fault reports get `reportedAt: '2026-08-31T00:00:00Z'` (static date)
- Every fault appears to be reported at the same time
- **Impact:** Housing office cannot see when faults were actually reported; report ordering is incorrect

### 10. Urgency Not Validated on Client
**File:** `public/app.js`, line 22
- Default to `'normal'` if no radio button checked
- `urgencyPicker()` function not defined, so no radio buttons exist anyway
- **Impact:** Combined with #1, urgency selection is broken

### 11. Echoed Submission Doesn't Preserve State on Errors
**File:** `public/app.js`, lines 34-39
- Error response echoes `submitted: req.body` but is not re-used to repopulate the form
- Tenant who gets validation errors must re-enter all data
- **Impact:** Poor recovery from validation errors; violates UX walkthrough

## Minor Issues

### 12. Missing Test Coverage
**File:** `test/validate.test.js`
- Only 3 test cases; missing edge cases
- No tests for `faults.js` or `server.js`
- No tests for empty descriptions, malformed urgency, concurrent writes
- **Impact:** Low confidence in reliability

### 13. No Error Logging
**File:** `src/faults.js`, `src/server.js`
- File I/O errors swallowed silently (line 7: bare `catch`)
- Session errors not logged
- **Impact:** Difficult to diagnose issues in production

## Blockers Summary
1. Undefined UI rendering functions (`propertyPicker`, `urgencyPicker`, `summary`)
2. Insufficient validation (empty descriptions, invalid properties, no room validation)
3. No concurrent access safety in data store
4. Session cookie won't work on HTTP connections

## Recommendation
**Do not release.** Entire report flow is broken due to missing UI functions. Core validation is incomplete. Data persistence is unsafe under concurrent load. Requires significant work before production readiness.
